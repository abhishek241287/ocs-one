## Implementation

The 70-H implementation adds:

- `scrap_documents.idempotency_key` with a unique constraint.
- `scrap_seq` for scrap document numbering.
- `(production_order_id, status)` index support for scrap documents.
- Handwritten `CreateScrapBody`, `ApproveScrapBody`, and `RejectScrapBody` schemas.
- Authenticated `/api/inventory/scrap` routes:
  - `POST /` creates a draft.
  - `POST /:id/approve` is director-only.
  - `POST /:id/reject` is supervisor/director.
  - `POST /:id/post` is supervisor/director.
  - `GET /` and `GET /:id` require authentication.
- D7 posting as two typed signed-ledger rows per WIP source row:
  - `SCRAP`, `−qty`, `stock_state=wip`
  - `SCRAP`, `+qty`, `stock_state=scrapped`
- WIP `scrapped_qty` and `remaining_qty` projection updates.
- Deterministic locking: scrap document first, WIP rows by `created_at`, then `id`.
- `scrap-idem:` transaction advisory locks and duplicate-key replay fallback.
- Source GRN-line validation before any ledger mutation.
- Outbox and security audit events for scrap lifecycle changes.

An exhausted WIP scope may still produce a draft; the post transaction rejects it with `OVER_SCRAP` and performs no mutation. This keeps workflow state visible while making the posting guard authoritative.
