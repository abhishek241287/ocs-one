NUMERIC MODEL (uses every Phase 0 column coherently)

Client supplies: type (positive|negative), quantity (the movement amount),

dims (lot? — REQUIRED for negative; optional for positive), warehouse

(NOT NULL), location?, bin?, reason, count_reference?.

Draft samples: systemQty = Σ ledger 'available' at the dims (at draft time).

Derived: physicalQty = systemQty + quantity (positive) | systemQty − quantity

(negative); variance = physical − system (DB CHECK) = ±quantity by construction.

Post writes: ADJUSTMENT_IN +qty 'available' (positive) / ADJUSTMENT_OUT

−qty 'available' (negative), dims from the document; source_line_id = the

lot's GRN line when lot-scoped, else NULL (warehouse-level positive adds are

the only NULL-lot case — un-lotted available stock, allocatable only after a

future lotting step; documented).

NEGATIVE-STOCK ARCHITECTURE (the important call): NEGATIVE adjustments MUST

be lot-scoped (422 otherwise). Rationale: lot-scoped negatives take the lot +

GRN-line FOR UPDATE — the SAME lock object transfers/allocate/issue hold —

so adjustment↔transfer/issue races on real stock are serialized. A

warehouse-level negative cannot exclude concurrent line-keyed consumers

without locking every line; forbidding it closes that hole by construction.

Negative protection: quantity ≤ available re-validated UNDER the locks at

post (draft-time sampling is informational only).

IDEMPOTENCY: Idempotency-Key on POST; in-tx advisory lock ('adjust-idem:')

+ unique column + dual-shape 23505 fallback; no pre-tx lookup (70-B pattern).

LOCKS at post: document FOR UPDATE → [lot FOR UPDATE → GRN line FOR UPDATE]

(negative, lot-scoped) or material-advisory 'reservation-material:' +

warehouse dims re-read (positive warehouse-level — additive only, no

oversell direction) → ledger. adjustment↔adjustment same lot serializes on

the lot row: loser 409, ZERO mutation.

async function availableAt(materialId: string, wh: string, loc?: string | null, lotId?: string | null): Promise {
const conds = [
eq(inventoryTransactionsTable.materialId, materialId),
eq(inventoryTransactionsTable.stockState, "available"),
eq(inventoryTransactionsTable.warehouseId, wh),
];
if (loc) conds.push(eq(inventoryTransactionsTable.locationId, loc));
if (lotId) conds.push(eq(inventoryTransactionsTable.lotId, lotId));
const [row] = await db.select({ sum: sql`coalesce(sum(${inventoryTransactionsTable.quantity}), 0)` })
.from(inventoryTransactionsTable).where(and(...conds));
return Number(row.sum);
}

function simpleTransition(allowed: string[], next: string, extra: Record<string, any> = {}) {
return async (req: Request, res: Response): Promise => {

if (!allowed.includes(r.status)) return { status: "invalid_state" as const, current: r.status };
const [u] = await tx.update(inventoryAdjustmentsTable).set({ ...nextFields(next), ...extra })
.where(eq(inventoryAdjustmentsTable.id, r.id)).returning();
return { status: "ok" as const, updated: u };

if (outcome.status === "not_found") { res.status(404).json({ error: "Adjustment not found" }); return; }

};
