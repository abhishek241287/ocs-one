── CRITICAL LOGIC 1 — ACTIVATION INTEGRITY (attributes & template versions):

Activation runs a dry-run BEFORE flipping status:

attribute: data_type valid; DROPDOWN ⇒ allowed_values non-empty;

unit_code ⇒ exists in unit_definitions; allowed_units ⊆ registry;

precision/scale/min/max consistent (scale ≤ precision when both set).

Fail → 422 TEMPLATE_INTEGRITY with the failing checks listed.

template version: ≥1 attribute; every attribute ACTIVE (not DRAFT/RETIRED);

sequences unique; NO overlap with another ACTIVE version's effective

range of the SAME template (A6 one-active-per-date) → 409 on overlap.

Activation is transactional; outbox ATTRIBUTE_ACTIVATED / TEMPLATE_VERSION

ACTIVATED in-tx.

── CRITICAL LOGIC 2 — PREVIEW (round-4 §18): GET /versions/:vid/preview

returns { template_code, version_no, status, effective_from/to, fields: [

{ attribute_code, name, data_type, required, sequence, default_value,

unit, allowed_values, min, max, precision, scale } ], generated_csv

columns: ["material_code","lot_number","quantity", ...attribute_codes] }

— the SAME payload 71-E uses to generate CSV headers (one definition,

three consumers). Preview available to any authed role.

── CRITICAL LOGIC 3 — MAPPING (A6 + Option A): create validates scope shape

(exactly one of material_id/category_id), template exists. DB partial

uniques enforce one-active; map 23505 (both code shapes) → 409

AMBIGUOUS_CONFIGURATION with the winning scope in details. Resolution

endpoint: GET /masters/resolve-template?material_id=&date=

→ loads candidate mappings + ACTIVE versions, calls resolveTemplate()

from 71-B, returns its result verbatim ({kind, template_id,

template_version_id} | NO_TEMPLATE | ERROR+reason). Any authed role.

── CRITICAL LOGIC 4 — PROFILE GUARD (A12): PUT profile validates the

transition: moving AWAY from the current mode is rejected 409

UNSAFE_TRANSITION if any ledger rows, lots, or wip rows exist for the

material (conservative reading; refine per real rules later — flag in

evidence). Creating a profile where none existed is always allowed.

── OUTBOX/SECURITY: every mutation writes the corresponding event

(UNIT_UPSERTED, ATTRIBUTE_CREATED/UPDATED/ACTIVATED/RETIRED, TEMPLATE

CREATED/UPDATED, TEMPLATE_VERSION_CREATED/ATTRIBUTE_ADDED/ACTIVATED/
