── D6 (ratified) — Return accounting ─────────────────────────────────────────

Physical return = −qty stock_state 'wip' + qty stock_state 'available'

(transactionType RETURN). The ledger 'returned' stock_state is RESERVED for

future customer/supplier returns and is NOT written by this flow.

Returns move physical WIP only — they NEVER restore reservation allocations,

NEVER touch issued/allocated arithmetic (un-issue is reversal's job, 70-D).

── D7 (ratified) — Scrap accounting ──────────────────────────────────────────

Physical scrap = −qty 'wip' + qty 'scrapped' (transactionType SCRAP).

'scrapped' is a distinct, visible stock state (zero value, never returns to

available). Never restores reservation allocations.

── D8 (ratified) — Physical adjustment flow ──────────────────────────────────

Domain = inventory_adjustments ONLY. State machine preserved:

draft → submitted → approved → posted | rejected. Approval is a GENUINE

control point (Director only). Positive = ADJUSTMENT_IN, negative =

ADJUSTMENT_OUT. The consumption /adjust endpoint REMAINS ANNOTATION-ONLY

(INV-P5-06 proves it physically silent). Negative-stock protection required.

── D9 (ratified) — Transfer lifecycle ────────────────────────────────────────

/transfer-requests. Lifecycle: draft → approved → issued → in_transit →

received → reconciled (+ cancelled pre-issue / rejected in-transit).

receive: in_transit → destination available (TRANSFER_IN). The existing

Option A material_transfers implementation is NOT modified (not rewritten,

not re-routed, not "merged").
