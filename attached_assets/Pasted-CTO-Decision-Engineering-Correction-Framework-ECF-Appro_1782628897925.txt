CTO Decision — Engineering Correction Framework (ECF)

Approved with the following architecture.

### Decision 1 — Storage Model

**Approved: Single Generic Engineering Corrections Ledger**

Do **not** create correction tables for every module.

Create one platform table:

engineering_corrections

Core fields:

* entityType
* entityId
* sequence
* correctionType
* reason
* previousValue (JSONB)
* newValue (JSONB)
* performedBy
* approvedBy
* approvedAt
* auditEventType
* metadata (JSONB)

This becomes the permanent engineering history of OCS One.

Module-specific tables remain the source of truth for current state.

The engineering_corrections table is the immutable history.

---

### Decision 2 — Scope

Build the framework now.

Migrate **only Cell Grading** during CW-02.

Do **not** migrate:

* Charging
* Testing
* QC
* Packing
* Dispatch
* Warranty

Those modules will adopt ECF during their own certification waves.

This keeps each wave independently certifiable.

---

### Platform Contract

EngineeringCorrectionService should expose only platform operations.

Example:

recordOriginal()

correct()

getHistory()

validateCorrection()

Each module supplies:

* Row lock
* Business rules
* State transitions
* Value recalculation
* Audit destination

The framework supplies:

* Append-only storage
* Sequence generation
* Immutability
* Authorization enforcement
* Reason validation
* History retrieval
* Common audit structure

---

### Additional Requirement

Include an entityType enum from day one.

Example values:

CELL

BATTERY

PACK

SHIPMENT

QC_RECORD

CHARGING_SESSION

TEST_RESULT

WARRANTY_CASE

Do not use free-text strings.

Future analytics and reporting will depend on this consistency.

---

### Future Vision

By CW-08 the Engineering Correction Framework should become one of the permanent platform services alongside:

* ODS
* RBAC
* Audit Framework
* Notification Framework
* Engineering Correction Framework

No module should implement its own correction engine after this point.

This is now an architectural law of OCS One.
