# OCS One – Sprint ODS 2.0

## Enterprise Design System Foundation

### What & Why

Build the OCS One Design System (ODS) into a complete enterprise UI framework.

No new ERP features are to be developed.

This sprint focuses on creating reusable UI components, layouts, design tokens, navigation patterns, and developer tooling so every future module uses the same foundation.

This sprint is an architectural investment that reduces future development effort, improves consistency, and enables rapid module development.

---

# OBJECTIVE

Every screen inside OCS One should eventually be assembled from ODS components.

No page should implement its own table, toolbar, drawer, dialog, or search bar.

ODS becomes the only UI framework used inside the application.

---

# PHASE 1 – CORE COMPONENT LIBRARY

Create a new folder:

```
src/components/ods/
```

Implement the following reusable components.

---

## OdsDataTable

This becomes the standard table component for OCS One.

Features:

* Search integration
* Filters
* Sorting
* Pagination
* Column resize
* Column visibility
* Density selector
* Sticky header
* Sticky first column
* Multi-row selection
* Bulk actions
* Loading skeleton
* Empty state
* Keyboard navigation
* Export hooks
* Responsive behaviour

Replace existing table implementations where practical.

---

## OdsToolbar

Universal toolbar.

Contains:

* Search
* Filters

* Export

No module should create its own toolbar.
