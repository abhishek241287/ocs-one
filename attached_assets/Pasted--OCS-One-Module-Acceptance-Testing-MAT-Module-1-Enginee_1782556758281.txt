# OCS One – Module Acceptance Testing (MAT)

## Module 1 – Engineering Masters Certification

Do NOT build any new features.

The goal is to certify the Engineering Masters module for production use.

This is a QA + stabilization sprint.

---

## OBJECTIVE

Every Engineering Master must be fully usable in a real factory.

Nothing moves to the next module until this passes.

---

## MODULES TO VERIFY

1. Product Master
2. Cell Master
3. BMS Master
4. Cabinet Master
5. Connector Master
6. Cable Master
7. Busbar Master
8. Charger Master
9. Test Equipment Master

---

## TEST 1 – CREATE

For every master:

Create a new record.

Verify:

✓ Required fields

✓ Validation

✓ Save button

✓ Database insert

✓ Success message

✓ Record visible after refresh

If save fails, fix the root cause.

---

## TEST 2 – EDIT

Open an existing record.

Modify multiple fields.

Save.

Refresh.

Verify changes persist.

---

## TEST 3 – SEARCH

Verify:

Search by code

Search by name

Partial search

Case insensitive search

---

## TEST 4 – FILTER

Verify:

Status filter

Category filter (where applicable)

Pagination

Sorting

---

## TEST 5 – DUPLICATES

Verify duplicate prevention.

Examples:

Duplicate Product Code

Duplicate Cell Code

Duplicate BMS Code

System must reject duplicates with a clear error.

---

## TEST 6 – STATUS

Verify:

Activate

Deactivate

Inactive records must not appear in downstream dropdowns.

---

## TEST 7 – RELATIONSHIPS

Product Master must correctly reference:

Cell Master

BMS Master

Cabinet Master

Connector Master

Busbar Master

Charger Master

Verify dropdowns populate correctly.

Verify selected values save correctly.

---

## TEST 8 – DATABASE

Verify every save actually inserts into PostgreSQL.

Check:

UUID

created_at

updated_at

status

revision

attachments

No NULL values where not allowed.

---

## TEST 9 – API

Verify:

POST

GET

PATCH

Status Toggle

Pagination

Search

All endpoints return proper validation errors.

---

## TEST 10 – UI

Verify:

Loading state

Empty state

Error state

Success toast

Validation messages

Responsive layout

---

## TEST 11 – SECURITY

Verify permissions.

Director

Create/Edit/Deactivate

Plant Manager

Create/Edit

Viewer

Read only

---

## TEST 12 – AUDIT

Every Create/Edit/Deactivate action must appear in Activity Logs.
