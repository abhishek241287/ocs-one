BATCH 70-B FIX — idempotency race (TOCTOU) on POST /:id/issue

Small surgical patch to artifacts/api-server/src/routes/inventory/reservations.ts.

No other files. Dev DB only. NO COMMIT.

ROOT CAUSE (Replit-verified): the idempotency SELECT ran BEFORE db.transaction,

so two concurrent same-key requests both missed, both entered transactions, and

the loser hit the unique constraint → raw 409 instead of a 200 replay.

FIX PATTERN: per-key advisory xact lock INSIDE the transaction, then re-check —

the classic insert-serialization approach already used by this codebase

(Task #69 create: pg_advisory_xact_lock('reservation-material:…')). Same-key

requests now serialize on the lock; the second waits for the first commit, then

its re-check finds the note → clean 200 replay. Different keys unaffected.

---------------------------------------------------------------------------

PATCH — in reservations.ts, POST /:id/issue handler:

(1) DELETE this entire pre-transaction block:

// Idempotent replay: same key → original note, nothing written.

.select()

.from(wipIssueNotesTable)

.where(eq(wipIssueNotesTable.idempotencyKey, idemKey))

.limit(1);

const lines = await tx.select().from(wipIssueLinesTable)

.where(eq(wipIssueLinesTable.wipIssueNoteId, existing.id));

return { status: "replay" as const, note: existing, lines };

}

}
